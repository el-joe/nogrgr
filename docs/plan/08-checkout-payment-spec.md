## 2. Inline card panel (Stripe; Authorize.Net / 2Checkout when their drivers exist)
**Client decision 2026-11-26 (final, decision #78 b): Stripe card fields are inline via Stripe.js (Card Element), like the old project.** Stripe.js (`js.stripe.com/v3`) is the only allowed external script, loaded on demand by `resources/js/core/payments/stripe-card.js` when Stripe is selected. Flow: place order → `payments/{order}/start` returns the PaymentIntent `client_secret` + `publishable_key` → `stripe.confirmCardPayment` in the panel (3-D Secure in Stripe's dialog) → `checkout/payment/stripe/{order}?status=success&reference=` where the server reads the intent and marks the order paid. **No webhook.** A declined card shows Stripe's message under the card element (`#stripe-card-errors`) and Pay retries the same intent. PayPal stays a redirect (Redirecting page → provider → return URL). The same card (Blade `<x-ui::stripe-card>`, same JS module) is used on the central registration payment step, vendor subscription / invoice modals, settlement, language purchase and request payments. Implemented: Stripe panel only (Authorize.Net / 2Checkout manual inputs join with their drivers).
Shown under the list only when that gateway is selected: `#inline-card-form mt-4 border-[#dcdcdc] rounded-[8px] p-4 bg-[#fafafe]` (Souqify `rounded-2xl border-neutral-200 bg-slate-50 p-5`); heading lock icon (#16a34a) + "Secure card details / تفاصيل البطاقة الآمنة". Stripe: Card Element box (`rounded-[6px] px-4 py-3 min-h-[42px]`), errors under it. Authorize.Net / 2Checkout: Card number (groups of 4), `MM / YY`, `CVC` inputs (numeric, cc autocomplete), errors `#card-errors`. Submit: no method → "Please select a payment method."; tokenise via SDK, then place order.
Strings: Card number/رقم البطاقة, MM / YY/شهر / سنة, CVC/رمز التحقق, Card error/خطأ في البطاقة.

## 3. Behaviour that stays identical vs. backend-only fixes (UI unchanged)
Identical: gateway filtering (tenant rows active, not hidden, type orders, centrally active, ready = connected + required keys), alphabetical order, nothing preselected, label never changes for redirect gateways, guards order in placeOrder (plan limit → validation → empty cart → shipping → country rules → gateways → still listed → live ping) with the same messages, flow `checkout/payment/{gateway}/{orderUuid}` → success / cancel → order status with toasts "Payment completed successfully." / "Payment was cancelled.", gateway-blocked page from limits, charges in USD.
Backend-only improvements (invisible to the customer; tech-lead approved direction): Stripe via PaymentIntents confirmed in the inline panel (3-D Secure via Stripe.js), the server verifies the intent status on return/confirm (no webhook, client 2026-11-26), transaction id = PaymentIntent id (refunds), amount checked against `amount_received`, SDK loaded on demand when Stripe is selected, 2Checkout publishable key bug fixed, Luhn/expiry hints only as SDK errors (no new UI).
**USD only (decision #87):** every gateway charge is USD; a non-USD display currency shows the converted total for reference plus “You will be charged $X USD.” in the payment section.
**COD (client confirmed 2026-11-25): hidden at checkout**, exactly like the old UI. Server-side COD support stays (admin/vendor manual orders), no storefront option.
